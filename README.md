# AI Context Manifest: Audience Response System (ARS)

## 1. System Overview
**Project Goal:** Build a highly performant, secure, and privacy-compliant (German DSGVO) Audience Response System (ARS) for educational environments (universities, lectures). 
**Context for AI Agents:** This document serves as the architectural master plan. You are to act as the executing Engineer. When implementing features, strictly adhere to the stack, the architectural constraints, and the sequential roadmap outlined below. 

The system handles both spontaneous interactions (like Tweedback) and prepared, structured examinations (like OnlineTED), with a heavy emphasis on real-time performance to handle "thundering herd" traffic spikes (200+ simultaneous users clicking at the exact same millisecond).

---

## 2. Core Architecture & Tech Stack
Do not deviate from these technologies unless explicitly instructed by the user.

- **Infrastructure:** Docker Compose (Self-hosted on Hetzner VM, Germany).
- **Backend (API & WebSockets):** Node.js, Fastify, Socket.io.
- **Database (Persistent):** PostgreSQL 16 + Drizzle ORM.
- **State/Cache (Volatile/Real-time):** Redis 7 (Crucial for buffering high-traffic Socket.io events).
- **Frontend (SPA):** React (Vite), TypeScript, TailwindCSS, Zustand (State), React-i18next.

### 🛑 Architectural Constraints & Security
1. **DSGVO (Privacy by Design):** STRICT anonymity for students. Zero IP address logging in the database. No external CDNs (e.g., Google Fonts must be bundled locally via `@fontsource`).
2. **The Redis Buffer:** Postgres is for persistent data only (Admins, Quiz Catalogs, Final Results). ALL live interactions (clicks, live chat, active rooms) MUST be buffered in Redis via WebSockets to prevent Postgres connection pool exhaustion during traffic spikes.
3. **Anti-Brute-Force:** Rooms are protected by a 6-digit alphanumeric code (`[a-z0-9]`). Global and endpoint-specific rate-limiting (backed by Redis) is mandatory.

## 3. Feature Matrix

### Admin & Core Functionality
- **Role-Based Access:** Super-Admin (can manage other admins) and normal Admins.
- **Room Management:** Rooms auto-delete after 24 hours via Cron/Redis TTL (can be manually extended).

### Live Room Features (Spontaneous)
- **Robust WebSockets:** Auto-reconnection logic for mobile devices switching from Wi-Fi to LTE.
- **Chatwall:** Anonymous Q&A. Students can ask and delete their own questions. Admins can check off/gray out answered questions.
- **Ad-Hoc Polls:** Quick, on-the-fly polling generated by the Admin and pinned to the top of the chatroom.

### Advanced Quiz Engine (Prepared)
- **Quiz Catalogs:** Created offline, saved in DB, and activated within a live room.
- **Media Support:** Upload images/attachments. Displayed inline or available for download.
- **Live Controls:** Timer, skip question functionality, and live results reveal.
- **Personalized Feedback:** Students see their specific answer vs. the correct answer (Right, Wrong, NaN/Unanswered).
- **Open Text Questions:** Students submit text. Admin sees a live feed of incoming answers.

### AI & Automation
- **Quiz Generation:** LLM integration to generate quiz questions via prompt.
- **Semantic Analysis:** AI embeddings / Regex to cluster and group identical or semantically similar open-text answers for the Admin.

## 5. Development Roadmap (The "General Parts")

The project is divided into 7 strict, sequential phases to avoid merge conflicts and ensure a stable architectural foundation.

* **Part 1: Infrastructure & DB Setup** (Docker, Postgres, Redis, Drizzle Schema).
* **Part 2: Backend Core & REST API** (Fastify, Auth, Admin CRUD, Rate Limiting).
* **Part 3: The Real-time Engine** (Socket.io, Redis state management, Room codes).
* **Part 4: Frontend Base** (React, Vite, Zustand, i18n, Local Assets/Fonts).
* **Part 5: Live Rooms & Chatwall** (WS integration, Anonymous Chat, Ad-hoc Polls).
* **Part 6: Advanced Quiz Engine** (Media uploads, Timers, Result statistics).
* **Part 7: AI Integration** (LLM Quiz generation, Open-text semantic clustering).

> **AI Agent Directive:** Before writing code, verify which "Part" you are currently implementing and ensure all dependencies from previous parts are met.
